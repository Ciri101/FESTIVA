# gate：检查与门控

本区区分两类检查：默认的队列机械检查，以及 [checks.md](checks.md) 中按项目配置的业务检查。效果评价与趋势分析另住 [eval](../eval/AGENTS.md)。

- 队列检查随工具运行，并由 init 接入 Git 的 pre-commit 与 pre-merge-commit；核对五状态/容量事件重放、配置、任务包/取消档案和实际暂存账本、历史、视图、封存卷、相关交付指纹及运行态排除。检查异常就拒绝提交，不把崩溃当通过。
- 现有 Git 钩子继续运行；不覆盖其内容或跳过其拒绝结果。保护接线异常时工具拒绝写账。
- 项目业务检查不因写在文件里就自动执行，由 Agent 按批准方案实际运行并汇报（[根契约](../AGENTS.md)第 15 条）。
- 调整已批准任务的验收方法，先按任务规则重新确认，不能临时降低标准。
- 本次读数归任务，通过 deliver 登记回执，不把本区改成最新结果账。
- 本区的检查只核对记录、配置与指纹，不验证申报的真实性；机器检查的边界见根契约第 2 条。

修改机械工具后运行本区的全部真实集成测试——[队列回归](test_task_queue.py)与[状态包回归](test_state_queue.py)，命令见 [checks.md](checks.md)——不以规则文案自证。返回 [根契约](../AGENTS.md)。
