# FESTIVA 项目目标

- 最后复核：2026-09-28
- 依据：用户对 FESTIVA 的项目说明，以及本项目现有 C4 图和高保真图片；本文件记录当前工作目标，不将图片中的示例内容视为已实现功能。

## 要解决的问题

国际学生在寻找和组织节日聚会时，需要同时判断活动是否适合自己、是否方便到达，以及参加条件是否清楚。FESTIVA 拟通过节日、食物和文化交流，帮助他们发现、创建和参加小型聚会。

## 当前交付目标

形成一套可审阅的 FESTIVA 产品、设计和工程文档，以现有高保真图片与 C4 图为输入，明确用户路径、界面行为、系统边界和待确认事项。经用户确认后，才把相关草稿作为后续 iOS 实现的基线。

目前已有：[高保真设计文档](FESTIVA-高保真设计文档.md)和[工程架构文档](FESTIVA-工程架构文档.md)。这两份文件还不是已批准的产品或技术决策。

## 完成的判断

- 文档能对应到实际参考图，区分图中事实、设计建议与待确认决定。
- 主要页面、活动流程、推荐/创建/个人资料边界和系统组件有可核对的描述。
- 用户审阅并明确确认需要成为正式基线的部分；未确认部分继续标为草稿。

## 范围与限制

- 当前阶段以文档和任务组织为主；不因导入模板而声称 iOS App、后端、数据库或 AI 服务已经实现。
- 项目资料位于 `reference/`，长期目标与经确认的要求位于 `truth/`，工作产物默认位于 `object/`；实际位置按任务确认。
- 安全、时间、交通、预算、饮食等参与约束需要在后续规格中明确；活动、名额、费用、认证和匹配分数不得由示例图或 AI 推测为真实数据。
- 三个角色 Patti、Conor、Lily 目前只在设计图中展示；其权限、数据隔离和写入行为须在正式产品规格中确认。

## 待决定的问题

- 最终产品设计与工程文档哪些内容获得批准。
- API 技术、LLM 与地图供应商、第三方数据边界和部署方式。
- 学生验证、申请审批、活动容量、地点可见性与推荐解释的详细规则。
- 队列窗口容量。当前工具配置沿用模板默认值 8，仅为运行参数，不代表产品决策。
