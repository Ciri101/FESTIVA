- 最后复核：2026-09-30
- 依据：用户对 FESTIVA 的项目说明、本项目的 C4 原图和高保真图片，以及经“定稿裁决单”确认的 38 项裁决（全文记录在任务 [T0003](../queue/tasks/T0003/task.md)）。本文件记录目标、范围和决定摘要；图片中的示例内容不视为已实现功能。

## 要解决的问题

国际学生在寻找和组织节日聚会时，需要同时判断活动是否适合自己、是否方便到达，以及参加条件是否清楚。FESTIVA 拟通过节日、食物和文化交流，帮助他们发现、创建和参加小型聚会。

## 项目用途

FESTIVA 是一个 Demo 项目，用于三件事：拍摄 Demo 视频、在 GitHub 开源、作为研究生产品设计申请的作品。取舍以这三个用途为准：界面和流程要能真实演示，仓库要能被他人直接查看和运行，架构要按正式产品的标准表达。

## 已定的方向

以下为摘要，依据编号对应 T0003 中的裁决，细则见各文档。

- **Demo 范围**：跑通“浏览 → 详情 → 申请 → 主办审批”和“创建活动”（A1）；三个 AI 角色都真实接入，每个角色做一个核心工具（R4）。
- **演示城市**：温哥华；地图本身不限区域，只是演示内容集中在温哥华（A2）。
- **AI 形态**：Patti、Conor、Lily 各负责 Join、Create、Me 一个板块，可以自由对话，按用户请求给出结构化结果；结构化结果经用户确认后才生效（B1、B3、B6、E4）。
- **架构分两层**：工程架构文档按正式产品级标准描述；Demo 开发版本使用本地数据，由用户自带密钥调用云端大模型，简化方案单独写在 Demo 架构方案中（R6）。
- **地图**：在 App 端显示；App 不做导航，只提供跳转到地图 App（D2、R1）。
- **定稿方式**：修订后逐节确认，确认的章节先定稿，其余继续标为草稿（F1）；文件名不带状态，状态写在文档头部（F2）；上文“文档结构”表中的五份文档加入状态包白名单，名单以 `charter/config.json` 为准；图纸区的文档不进白名单（F3，见[图纸区规则](architecture/AGENTS.md)）。
- **技术选型**：云端大模型暂定 Qwen API，演示与正式架构都用，经适配器接入；正式架构的 API 服务与 AI 编排服务用 Swift 编写、沿用 Demo 的业务核心，在同一容器平台上分别部署，数据库为托管 PostgreSQL；邮件服务商、对象存储供应商、容器平台与 Swift 服务端框架暂缓（任务 [T0016](../queue/tasks/T0016/task.md)）。
