# truth：项目长期要求

本区回答“项目要做成什么”，不回答“某件任务进行到了哪里”。

- [goals.md](goals.md) 记录项目目标，并列出本区的文档结构。确有需要才新增设计、架构或领域规则文档，不预建空文档树。
- 已确认的要求与尚待决定的问题分开写；草案不能被当成用户已批准的要求。
- 项目要求发生变化时，先取得用户明确同意，在任务里记录决定，再更新此处；文档链接到决定所在任务，不复制整段裁决。
- 保留最后复核日期。复核节奏由项目自行决定，不默认承诺自动过期提醒。
- 临时方案、验证证据与交接说明放任务卷；外部资料与原始参考图放 [reference/](../reference/)。
- 定稿的系统架构图住 [architecture/](architecture/AGENTS.md)，有自己的区规则与制图规范；画图、改图前先读那里。

本区文档是直接编辑的正本，不是生成视图。返回 [根契约](../AGENTS.md)。
