# 待决事项裁决单

## 范围

- 要交付：
  1. 裁决单：汇总下列来源的全部待决项，逐项写明来源、内容、分组、选项、建议与依据。分组为：已被后续决定解决；假设（整组确认，只挑出不同意的）；只影响正式服务端（建议记为“实现正式服务端时再定”）；现在决定（影响产品规则或 Demo 实现）。来源：C1、C2、API 服务 C3、iOS App C3、AI 编排服务 C3 设计说明回述中的假设与未定义的边界；产品设计文档第 11 节 2 项；高保真设计文档第 5 节 W1-1；工程架构文档第 7 节（学校与邮箱域名对应表由谁维护）与第 13 节（服务等级、监控与恢复目标）。裁决单在对话中分组呈给用户，可分一至两轮。
  2. 用户的裁决记入本任务的过程记录（交接说明）与回执，逐项可查。
  3. 五份设计说明的回述：每条假设与边界注明结果与所在任务；头部 version 与 date 随之更新。
- 不包含：把裁决写入产品设计文档、工程架构文档、高保真设计文档与 Demo 架构方案（另立任务）；图纸结构的变更（若某项裁决要求改图，停下另行决定）；实现；推送到 GitHub。
- 允许修改的位置：truth/architecture/ 下 festiva-c1、festiva-c2、festiva-c3-api、festiva-c3-app、festiva-c3-ai 五份设计说明（仅限回述中的假设与边界条目、头部 version 与 date）；队列文件经工具维护。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| A1 | 裁决单完整 | 对照五份设计说明的回述与各文档的待确认项逐项核对 | 全部待决项列入，无遗漏、无重复；每项有分组、选项与建议 |
| A2 | 每项都有用户的裁决 | 阅读过程记录与回执 | 每项都有结果；“实现正式服务端时再定”一组经用户同意 |
| A3 | 设计说明注明结果 | 阅读五份设计说明的回述 | 每条假设与边界都注明结果与所在任务；组件、边表与图源未动 |
| A4 | 制图检查为绿 | 运行 `tool/diagram/check.mts`；提交时钩子再检查 | 三项无红 |
| A5 | 没有越界 | `git diff` | 只改允许的位置 |

验收安排：Agent 自检后交付；用户验收。
