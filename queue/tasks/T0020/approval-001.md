# C3：AI 编排服务组件图

## 来源与目的

2026-09-29，用户请 Agent 基于 C1、C2 与 Demo 架构方案评估 C3 的范围后决定：API 服务、iOS App、AI 编排服务都画 C3，顺序为 API 服务 → iOS App → AI 编排服务，按顺序设依赖。本件是第三件，前置是《C3：API 服务组件图》与《C3：iOS App 组件图（MVVM）》。

画 AI 编排服务的理由：它有自己要守的规则，包括只读、确认后才生效（B1），角色之间只共享已确认的内容（B2），偏好默认是软条件（B4），没有同意就拒绝（C9），事实只来自工具结果，每个角色只有一个工具（R4）。接入云端大模型（暂定 Qwen API，任务 [T0016](../T0016/task.md)）是规范中“接第三家改几个框”的典型，Demo 的演示脚本是同一接口的假实现。按 T0016 的决定，正式服务端沿用 Demo 的 AI 模块，所以本图的组件划分同时就是 Demo 中 AI 模块的内部结构。它的工具执行依赖 API 服务的只读接口（C2 边 7），对话入口对接 App 的对话客户端（C2 边 3），所以排在两者之后。
