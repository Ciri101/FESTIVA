# 规则缺口：已取消活动与改性别、对话记录截取、工具校验规则

## 范围

- 要交付：
  1. 第 1 项：取得用户的决定（Agent 建议冻结优先：已取消活动中的记录不因修改性别而改变），写入产品设计文档 7.2，必要时同步 6.1 中修改性别前的提示。工程架构文档第 8 节补 V2 的冻结，写明修改性别时处理哪些活动；附录补 V2。API 服务 C3 设计说明第 4 节“修改性别”一条视需要相应修改。
  2. 第 2 项：V10 写入工程架构文档第 5.3 节“对话记录”与 Demo 架构方案第 10.1 节，截取的轮数在实现时按所选型号确定。
  3. 第 3 项：产品设计文档 5.1 写明结束时间须晚于开始时间，以及交流语言的取值方式；推荐卡数量按用户的决定写入产品 3.2，或写明为实现参数。AI 编排服务 C3 设计说明边 5–7 的语义栏与 Demo 架构方案第 10.2 节改为引用产品设计文档。若新增交流语言的固定列表，Demo 架构方案第 7.2 节写明其来源，工程架构文档第 7 节视需要补上。
  4. 改动的已确认章节须用户重新确认；头部、章节状态、状态行与附录随之更新；设计说明头部的 version、date 与状态行随之更新。
- 不包含：其他过时文字（第二件任务）；重复内容的整理（第三件任务）；实现；推送到 GitHub。
- 允许修改的位置：truth/FESTIVA-产品设计文档.md（头部、章节状态、第 3.2、5.1、6.1、7.2 节与附录）；truth/FESTIVA-工程架构文档.md（头部、第 5.3、7、8 节与附录）；truth/demo/FESTIVA-Demo架构方案.md（头部、章节状态、第 7.2、9、10.1、10.2 节与附录）；truth/architecture/festiva-c3-ai/festiva-c3-ai.md（头部与状态行、第 3 节边 5–7 的语义栏）；truth/architecture/festiva-c3-api/festiva-c3-api.md（头部与状态行、第 4 节）；队列文件经工具维护。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| A1 | 已取消活动遇到修改性别时的处理有明确规则 | 阅读产品设计文档 7.2 与工程架构文档第 8 节 | 按用户的决定写明，两处一致；工程架构文档第 8 节有 V2 的冻结 |
| A2 | V10 落到实现依据中 | 阅读工程架构文档第 5.3 节与 Demo 架构方案第 10.1 节 | 都写明只带最近若干轮、轮数在实现时确定 |
| A3 | 工具校验规则在产品设计文档中有出处 | 阅读产品设计文档 5.1、3.2，AI 编排服务 C3 边 5–7，Demo 架构方案第 10.2 节 | 结束晚于开始、交流语言的取值、推荐卡数量在产品设计文档中有出处，或写明为实现参数；C3 与 Demo 引用它，互不矛盾 |
| A4 | 已确认章节经用户重新确认 | 用户在对话中确认 | 状态据此更新 |
| A5 | 检查为绿、链接可用 | 运行 `tool/diagram/check.mts`；本地相对链接检查 | 无红；无断链 |
| A6 | 没有越界 | `git diff` | 只改允许的位置 |

验收安排：Agent 自检后交付；用户验收。
