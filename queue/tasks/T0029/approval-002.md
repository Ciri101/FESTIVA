# 申请人通知的入口

## 来源与目的

2026-09-30，任务 T0028 评估 Demo 架构方案时发现：产品设计文档 7.3 规定申请人在申请被通过、被拒绝或活动取消时收到通知，但界面只在 Create 首页有铃铛，点进去是主办人看的“申请通知”（图 281）；申请人从哪里看到自己的通知，产品设计文档与高保真设计文档都没有写。用户选择：铃铛只给主办人；申请人的通知在 Me 首页的“我的申请”显示未读角标，点进去看到状态变化（当前对话）。理由：主办人的事在 Create 板块，参加者的事在 Me 板块，与三个板块的分工一致，已确认的申请通知页不用改。
