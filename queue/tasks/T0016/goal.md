# 论证并决定未定型的技术方案

## 范围

- 要交付：
  1. 逐项论证以下事项：API 服务的技术与部署方式（R5 的托管后端服务只是候选）；AI 编排服务是否与 API 服务部署在同一平台，以及它的运行形态；云端大模型供应商（须支持工具调用与结构化输出）；邮件发送服务商；对象存储。数据库 PostgreSQL 如有必要一并复核。
  2. 每项给出：候选、评价标准、比较表、资料来源与读取日期、推荐及理由；评价标准先与用户确认。
  3. 用户逐项作出决定，或明确暂缓；决定与理由写进任务回执。
  4. 把决定写进 truth：工程架构文档第 3 节（技术标签与相关说明）、第 15 节（待确认事项）及头部、章节状态、附录；项目目标“待决定的问题”；大模型供应商有定论时，同步 Demo 架构方案第 3、16 节中与供应商有关的文字。
  5. 技术标签变化按结构变更走：C2 图源、边表、设计说明、SVG 与可移植 SVG 同批更新，三项检查为绿、夹具 FAIL 0。
- 不包含：实现或部署任何服务；注册账号、申请密钥、购买或试用付费服务；C3 组件图；产品规则；推送到 GitHub。
- 允许修改的位置：truth/FESTIVA-工程架构文档.md（头部、章节状态、第 3 节、第 15 节、附录对照）；truth/architecture/festiva-c2/ 与 truth/architecture/ 下两份清单（后者由工具生成）；truth/goals.md（“待决定的问题”与最后复核日期）；truth/demo/FESTIVA-Demo架构方案.md（第 3、16 节中与大模型供应商有关的文字）；队列文件经工具维护。
- 外部动作：论证需要只读查阅供应商的公开文档与价格页。是否允许联网查阅，由用户在批准本任务时明确；不注册、不付费、不提交任何个人信息。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| A1 | 每项都有论证 | 阅读任务回执 | 每项有候选、经用户确认的评价标准、比较表、资料来源与日期、推荐及理由 |
| A2 | 每项都有用户决定 | 用户在对话中逐项决定 | 每项为“已定”或“明确暂缓”，回执写明决定与理由 |
| A3 | truth 与决定一致 | 对照回执阅读工程架构文档第 3、15 节、项目目标与 Demo 架构方案相关节 | 已定事项不再列为待确认，暂缓事项仍列出；文字一致 |
| A4 | C2 同步且检查为绿 | 运行 `tool/diagram/check.mts` 与夹具 `tool/diagram/render-diagrams-accept.mts`；目检 C2 SVG | 技术标签与决定一致；三项检查为绿；夹具 FAIL 0、SKIP 0；文字不截断 |
| A5 | 没有越界，也没有外部动作 | `git diff`；回执列出的联网记录 | 只改允许的位置；没有注册、付费或提交信息 |

验收安排：Agent 自检后交付，标明未独立验证的部分；用户验收。
