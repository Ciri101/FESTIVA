# 产品设计文档编写

## 范围

- 要交付：新建 truth/FESTIVA-产品设计文档.md：
  1. 用户与场景；产品范围（Join、Create、Me 三个板块）；Demo 范围与演示城市。
  2. 三个 AI 角色（Patti、Conor、Lily）的职责、对话方式、结构化输出与用户确认卡片；角色间共享的信息。
  3. 推荐规则：主办方硬条件、参与者软偏好、理由标签。
  4. 活动字段清单；认证；性别；申请、审批与名额规则；地址可见范围；时间；预算；筛选（去掉交通方式，距离按当前定位）；个人资料与隐私（删除 Address，性别公开）。
  5. 按 A3 定义缺失页面的功能：搜索结果、申请结果、我的申请、活动管理、注册（含性别）、空状态与错误状态。
  6. 待确认项；裁决→章节对照表；按 F1 为每节标状态。
  内容可取材于现有高保真设计草稿中的规则类问题，但不复制界面描述。
- 不包含：界面与视觉描述（归 UI 设计文档）；工程实现（归工程架构文档）；修改 reference/ 中的图片。
- 允许修改的位置：新建 truth/FESTIVA-产品设计文档.md。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| A1 | 本文件负责的裁决全部落实 | 按裁决→章节对照表逐题核对 | 每题有对应章节，内容与裁决及覆盖关系一致 |
| A2 | 规则与参考图不矛盾 | 按 gate/checks.md“FESTIVA 文档与参考图核对”核对涉及画面的陈述 | 没有与图片矛盾的事实陈述；样例数据不被写成真实数据 |
| A3 | 已定规则与待确认分开 | 阅读全文 | 两类内容有明确标识 |
| A4 | 缺失页面有可实现的功能定义 | 阅读对应章节 | 每个页面写明入口、内容、主要操作与状态 |

验收安排：Agent 自检后交付；学生逐节审阅确认，老师验收。
