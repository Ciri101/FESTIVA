# 在 GitHub Desktop 中发布 FESTIVA 项目

## 范围

- 要交付：将现有本地 Git 仓库加入 GitHub Desktop；检查待提交文件；提交 FESTIVA 当前项目内容；创建并发布私有 GitHub 仓库；核对远端 URL 与已推送提交。
- 不包含：公开仓库、批准设计/工程草稿、修改 FESTIVA 产品功能、为模板接入任务记录用户验收通过。
- 允许修改的位置：当前本地仓库的 Git 暂存区、提交与远端配置；通过队列工具更新本任务机器账和视图。现有项目正文不因发布任务任意改写。

## 验收标准与验证方法

| 编号 | 可观察的结果 | 验证方法 | 通过条件 |
|---|---|---|---|
| A1 | GitHub Desktop 管理“留学生派对”本地目录 | 在 Desktop 检查当前仓库路径 | 路径为 /Users/shixinyue/Desktop/留学生派对 |
| A2 | FESTIVA 内容已提交，未含本机运行态或凭据 | 查看待提交列表与 Git 状态/忽略规则 | 参考图、草稿、规则和任务账在提交中；.shell/local、.DS_Store 不在提交中 |
| A3 | 项目作为私有仓库发布到 GitHub | Desktop 发布页及远端查询 | 私有仓库创建成功，origin 指向用户账户下的 FESTIVA 仓库，远端含本次提交 |

验收安排：Agent 自检上传状态，结果交付给用户；是否满意仍由用户判断。
